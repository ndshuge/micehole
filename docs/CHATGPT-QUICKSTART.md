# 在 ChatGPT 里用 MiceHole｜手机远程施工与本机执行指南

> **先明确范围**：MiceHole 不会向用户额外收取模型 API 费用，AI 推理由用户自己的 ChatGPT / 兼容 MCP 客户端提供。但 ChatGPT 不是无额度限制的免费算力，且不同账号、端、工作区能否使用自定义写入型 MCP 插件取决于官方支持。当前公开预览包只包括 **本地 stdio MCP 引擎**，尚未提供人人可用的一键手机远程连接流程。

## 一、作者现有的 MiceHole 怎么用？

> **不是新装的插件**：目前 ChatGPT 中已有 `Mice_Hole`（正式入口）和 `Mouse_Hole_Next`（旧测试/更新入口）；已验证二者连接相同的本机运行进程和工具架构。新建的 `MiceHole Universal Preview` 是 GitHub 安装包工程，**没有创建任何新的 ChatGPT 插件，也没有替换现有远程连接**。

**你已经具备远程连接时，可以直接照下面操作。**

1. 打开 ChatGPT 对话，先确认设置 → Plugins 中 MiceHole 已连接，或在消息输入框输入 @ 并选中 MiceHole。界面也可能在 + → Plugins / Apps 下。
2. 目前优先选择 **Mice_Hole**。`Mouse_Hole_Next` 现阶段指向同一个运行端，属于重复测试入口；不需要两个同时选中。Universal Preview 不会自动出现在 ChatGPT 的插件列表里。
3. **第一次先发只读检查**，不要立刻让 AI 自主修改重要文件：

> @MiceHole 请检查连接状态，说明当前授权工作区、可用工具和正在运行的施工进程。只读取信息，暂时不要修改文件或执行高风险命令。

4. **再试小项目**，建议先使用测试目录：

> @MiceHole 在我授权的工作区创建一个简单的网页计数器工程，写好 HTML/CSS/JS，运行必要的本地检查，并告诉我怎么预览。不要动其他项目，也不要添加开机启动或联网服务。

5. **进入真正的施工**：

> @MiceHole 检查当前项目，先理解已有结构，再按目标完成修改。每次改动后运行测试；失败时分析错误并继续修复；长进程使用 start/wait/output，直到验收通过或者遇到明确阻断再总结。不要只给我代码片段，要在本机真实执行。不得修改授权工作区之外的文件。

6. 在手机端使用时，**前提是当前账号、ChatGPT 界面和已连接的远程应用确实允许调用这些工具**。在新一条需要工具的消息里重新 @MiceHole 或用 + 选择插件，避免只在文本里讨论而没有实际工具调用。
7. 实际权限确认弹窗以 ChatGPT 提示为准。任何软件安装、删除数据、网络公开暴露、凭据使用、系统设置修改都要由用户单独授权。

## 二、普通用户第一次安装（GitHub 预览版）

### 方案 A：支持本地 stdio MCP 的客户端（已实现）

当前公开预览版支持这个链路：本机 Windows 安装包 → 本地 stdio MCP 客户端 → AI 模型 → 执行工程。

1. 从审核通过的 GitHub Releases 安装 MiceHole Universal。
2. 在安装目录运行 scripts/doctor.cmd，确认工作区和服务状态。
3. 阅读 [安全说明](SECURITY.md)。终端执行默认关闭，需要明确开启；本机 shell 不是安全沙盒。
4. 在**确实支持本地 stdio MCP** 的客户端中配置 MiceHole 的绝对启动路径。示例见 [CONNECT.md](CONNECT.md)。
5. 先运行只读状态检查，再在测试项目试用。

> ChatGPT Desktop 可承载部分本地 MCP 插件；将本地插件保存到账号**不会**自动让网页版或手机端获得本机执行能力。具体功能以客户端支持为准。

### 方案 B：手机 / 网页 ChatGPT 远程连接（作者原版可用，公开通用版尚未完成）

这是 MiceHole 的主打愿景和作者私有环境曾使用的方式，但**通用安装包尚未提供面向任意新用户的完整连接流程**。

预期架构：

- Windows 电脑运行 MiceHole 执行端；
- 用独立、加密、已认证的 MCP 远程连接/隧道将其接入受支持的 ChatGPT 插件；
- 用户在 ChatGPT 消息中选中 MiceHole、发出施工任务；
- MiceHole 在授权目录执行操作并反馈结果。

**不要**直接开放裸露的本机终端 HTTP 端口、在网上分享密钥、让陌生人直接调用你的电脑。需要每用户认证、访问控制和严格权限审查。

## 三、ChatGPT 端安装/启用：按官方当前能力

**已发布、且你的账号可用的插件**：进入 ChatGPT 侧边栏 **Plugins**，找到并安装对应插件，按提示完成连接；发消息时可以直接 @MiceHole，或通过输入框的 + / Plugins 菜单选择（具体以你的 App 界面为准）。需要工具继续执行的后续消息可再次选择插件。**从 GitHub 下载 Windows EXE 并不会自动将 ChatGPT 插件安装到账号上。**

**自行创建自定义远程 MCP 应用**：官方文档列出的完整写入型 MCP 开发者模式主要在 Business、Enterprise、Edu 的网页版逐步开放，由工作区管理员/授权开发者开启并配置 HTTPS MCP 端点和认证，扫描工具后才能在聊天中使用。并不意味着所有 Free/Plus 用户都具备一样的写入权限或可在移动端创建/使用自定义 MCP 应用。

## 四、推荐的 4 条自然语言指令（可直接复制）

| 场景 | 直接在 ChatGPT 里说 |
| --- | --- |
| 检查可用性 | “@MiceHole 先检查本机连接、当前项目和允许执行的操作；不要修改任何内容。” |
| 修改网页 | “@MiceHole 打开已授权的网页工程，修复移动端排版问题；运行检查并报告修改文件。” |
| 运行项目 | “@MiceHole 帮我运行这个工程，把启动输出和错误展示出来，先不要安装新的依赖。” |
| 长任务 | “@MiceHole 按验收标准完成这个功能，运行测试、根据失败继续修复；每轮给出变更摘要和真实测试证据。” |

**关键习惯**：始终说明授权项目路径、目标效果、验证方式和不能触碰的范围。不要把“有工具”误认为“已获得所有文件和系统操作许可”。

## 五、常见疑问

**免费吗？** 主要卖点是**用已有 ChatGPT 额度 + 本机 MiceHole 执行层获得类似 Codex 的工程体验**，无需为 MiceHole 另购一套模型 API。实际 AI 使用受 ChatGPT / 第三方客户端套餐、模型限制与自定义连接权限约束；安装包是否自由分发、许可方式以后续正式公告为准。

**能把 ChatGPT 额度转换成 API 吗？** 不能。它不向你输出 ChatGPT 的模型 API，而是让支持的 ChatGPT 对话直接调用 MCP 工具。

**为什么我手机上没有这个插件？** 自定义 MCP 的移动支持与套餐受官方限制。作者私有环境能用，不意味着新的 Free/Plus 账号可以直接复制。

**断线能一直自动施工吗？** 不能保证。进程管理与 ChatGPT 主动执行能力不同；聊天结束、配额耗尽、审批等待、网络断开可能让 Agent 停下来。

**为什么需要开电脑？** 任务在你自己的 Windows 机器执行，电脑必须开机、服务可连接，且项目目录有权限。

**需要安装 Blender/Godot 吗？** 不需要，通用版不依赖任何专业创作工具。
