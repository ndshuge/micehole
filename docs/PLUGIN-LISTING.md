# MiceHole 的 ChatGPT 插件页文案（建议稿）

本文件是给 GPT / ChatGPT 端**插件目录介绍**和安装引导使用的产品文案。**尚未更改你当前已连接的 `Mice_Hole`、`Mouse_Hole_Next` 两个入口，也没有创建第三个 ChatGPT 插件。** Universal 是可发布的本机工程，不等于一个已上线的 ChatGPT 插件。

## 名称 / Title

**MiceHole**

## 一句话介绍（主宣传语）

**手机一句话，电脑真施工。用已有 ChatGPT 额度获得免费 Codex 式体验。**

副标题：**像用 Codex 一样在 ChatGPT 里下达需求，让 MiceHole 在 Windows 本机修改工程、运行程序、检查错误、持续修复。不用另买一套模型 API。**

English: **Your ChatGPT quota. Your own PC. Code remotely, Codex-style.**

## 插件短描述（适合商店列表）

**让 ChatGPT 直接在你的 Windows 电脑上写代码、运行测试、修复 Bug。无需为 MiceHole 另购模型 API；支持远程施工的账号和客户端以实际接入能力为准。**

## 插件长描述（适合详情页）

MiceHole 为 ChatGPT 添加一个真正可执行的 Windows 本机工程工具层。告诉 ChatGPT 你要完成什么，它便可以在授权工作区读取代码、修改文件、运行项目、等待长进程完成、分析测试结果，并继续迭代。

无需把整个工程搬到云端，也不用为 MiceHole 自己的模型另买 API。适合编程学习、个人项目、网页开发和远程检查工程。作者的私有远程部署曾用于从手机 ChatGPT 操作电脑；公开 Universal 预览版当前仍限于本机 MCP，移动端远程接入尚未对所有账号完成适配。

**重要说明**：MiceHole 独立于 OpenAI，不是官方 Codex。你的 ChatGPT 订阅、使用额度和自定义 MCP 连接权限依然生效。本机终端运行的命令可能拥有 Windows 用户权限；仅允许在你授权的项目里使用，敏感操作需要确认。

## 推荐的示例提问 / Starter prompts

- “@MiceHole 检查我的项目，告诉我现在哪里有问题，先不要修改。”
- “帮我修复这个网页的手机端适配，在电脑上运行并测试。”
- “在授权的文件夹搭一个小网站，不要只输出代码，直接在本机构建。”
- “继续昨天的工程：读取现有进度，运行测试，修复未通过的部分。”

## 新手首次连接时看到的提示

1. 确认电脑上运行 MiceHole，且当前 ChatGPT 客户端具备对应应用使用权限。
2. 先调用只读状态检查，确认授权工作区。
3. 从一个可随时删除的测试项目开始。
4. 需要执行代码时先阅读权限说明；对修改系统设置、删除重要数据、读取凭据等敏感操作单独确认。
5. 更多说明见 docs/CHATGPT-QUICKSTART.md。

## 建议 ChatGPT 端功能表述

- “使用现有 ChatGPT 额度”：指已具备相应应用权限的 ChatGPT 用户可由聊天模型发起工具调用，不是把 ChatGPT 额度转换为 API，也不保证永远免费或不限量。
- “远程手机施工”：作者原有私有部署展示过此方向；公共安装包暂不提供任意账号一键接入。
- “类似免费 Codex”：营销类比，不代表 Codex 官方服务、相同模型、相同质量或相同价格。
- “无需专业软件”：只表示通用引擎不依赖 Godot / Blender / Unity / ComfyUI，不意味着所有任务零依赖。

## 推荐的默认行为约束

- 先确认目标工作区与具体成果，再读文件，最后写入。
- 尽量直接通过工具执行而不是只贴出代码。
- 每次修改后运行合理测试并报告实际结果；没有运行就明确说明未验证。
- 长任务优先使用 process.start / wait / output 追踪；遇到阻断明确报告。
- 禁止越过用户授权目录去读取密钥、配置凭据或私有数据。
- 外部传输、软件购买、系统配置变更、永久删除和公网服务必须单独取得用户明确许可。
- 不要承诺后台无限运行；离线 / 配额 / 审批 / 权限都可能中断。
