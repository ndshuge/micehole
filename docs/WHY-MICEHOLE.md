# 为什么做 MiceHole？

> 让 ChatGPT 不仅提出建议，还能在用户授权的电脑上真正完成操作。

## 初衷

最初我们希望用自然语言完成完整工程：阅读仓库、修改代码、运行测试、发现错误、修复错误，而不是让 AI 给一段代码，再让人反复复制、粘贴、运行、截图。MiceHole 不是第二个大模型，而是连接 ChatGPT 与 Windows 的工具桥。

## 设计原则

- **ChatGPT 做主要决策**：工具层尽量薄，不重复搭建复杂 Agent 队列。
- **小步施工、真实验收**：调用、观察结果、纠错，而非把“任务已提交”当成完成。
- **短会话 + Markdown 记忆**：PROJECT.md、STATUS.md、TODO.md、LOG.md 保存工程状态，降低对无限长会话的依赖。
- **CLI/结构化浏览器优先**：GUI 需要桌面焦点，多个 Agent 争抢时容易误操作。
- **可移植**：每位用户的磁盘、用户名、工作区、Tunnel ID、网络与认证独立。
- **工程节制**：质疑需求、删除冗余、简化、加快，再自动化；不能牺牲验证。

## 与 Codex 有何不同？

| 对比 | MiceHole + ChatGPT | Codex |
|---|---|---|
| 用户入口 | 普通 ChatGPT 对话中已授权的 MCP 工具 | Codex 专用工作流 |
| 真实执行位置 | 用户自己的 Windows | 由 Codex 模式与环境决定 |
| 模型 | 不单独购买 MiceHole 专属编码模型 API | Codex 自身的模型与产品体系 |
| 权限与隔离 | 运行用户自行管理；**不能默认为安全沙箱** | 有专门产品级执行与环境设计 |
| 持续性 | MCP 进程 + 工程状态文件，实际稳定性需验收 | 按 Codex 的产品工作流提供 |

“类似远程 Codex”主要指**用自然语言驱动编码—测试—修复闭环**，不意味着两者完全等价、无限制使用或完全免费。ChatGPT/Tunnel 资格、额度和其他成本依旧存在。

## 一个典型任务

> 在我的测试项目里审查当前代码，列出计划，修改页面，运行测试并收集错误。每完成一阶段更新 STATUS.md。如果需要系统权限、安装程序或访问私人数据，请先征得我的授权。
