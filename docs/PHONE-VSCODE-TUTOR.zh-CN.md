# 手机 ChatGPT × Windows × VS Code：MiceHole 编程老师实战

本教程以 **v3.0.1 的 12 工具 Direct 版**为基础说明可执行流程。MiceHole 不是 AI 模型、VS Code 插件、远程桌面，也不提供额外 ChatGPT/Codex 额度。需要个人已获准的 ChatGPT MCP 功能、私人认证 Tunnel、运行中的 Windows 端和用户授权。

## 1. 从手机到电脑，究竟发生什么

1. 手机（或网页）ChatGPT 接到“检查我的 Python 作业”。
2. GPT 通过获授权的 MCP 调用 MiceHole，**读取用户指定项目路径**，理解实际代码。
3. GPT 针对循环、条件、变量、输出提出问题，让学生先回答或自行在 VS Code 修改。
4. 学生允许后，GPT 运行指定的 Python 文件或安全测试，查看真实退出码、标准输出与报错。
5. GPT 按实际运行结果反馈错误原因和边界用例；需要时再验收下一轮。

**重要：**“操作 VS Code 项目”通常不等于接管 VS Code 窗口。MiceHole 可以通过文件和命令访问 VS Code 正在编辑的同一目录；只有确实需要点选编辑器界面时，才考虑已授权的 `gui` 工具。GUI 受窗口匹配、前台授权、Windows 焦点限制与使用者正在操作电脑等情况约束，不能保证可用。

## 2. 五分钟演示：学生自己写，AI 负责审查

先在 Windows 中手动创建**可丢弃**的练习目录，保存一个没有个人隐私的 `exercise.py`。在手机 ChatGPT 发：

> 请做我的 Python 计算机老师。先确认你连接的是我主动授权的 MiceHole。仅检查我明确指定的练习目录，不得浏览其他路径。先只读分析 exercise.py，判断循环、判断条件和变量是否正确，但不要直接给完整解法，也不要替我修改文件。先出一道选择题，等我回答。接着我在 VS Code 亲手修改；我说“检查”时，你再运行指定程序，展示执行命令、退出码、输出、报错及具体错误位置。先从直觉解释，再分析原理，最后在验收后给标准写法和一道变式题。遇到访问私人文件、安装软件、网络上传、系统设置或窗口抢焦点，要先问我。

建议的首个练习：用三层循环生成数字互不相同的三位数。检查 `range` 的上下界、百位不能为零、`if` 去重、`count` 位置和输出；不要在未得到学生回答时直接揭晓。

**验收标准：**
- [ ] GPT 正确指出文件路径、读取范围，未读取不相关目录
- [ ] 学生尚未同意改写时，`git diff` / 文件内容未改变
- [ ] 执行命令、退出码和输出可回查，不把“看上去正确”当成测试通过
- [ ] 学生修改后再次运行，并对失败和通过用例分别说明
- [ ] 变式题由学生作答，不自动代写提交内容

## 3. 其他有价值的真实场景

| 在手机下命令 | GPT 所做的思考 | MiceHole 的电脑操作 |
| --- | --- | --- |
| 帮我检查 Python/C 作业 | 诊断、出题、解释、批改 | 只读文件、运行已授权测试 |
| 帮我改网页布局 | 规划、检查视觉与回归风险 | 编辑指定 HTML/CSS、验证、在条件允许时观察页面 |
| 为什么程序报错 | 分析堆栈和失败原因 | 获取实际日志、退出码、Git 差异 |
| 继续昨天的工程 | 解读项目状态、制定下一步 | 按需读取 PROJECT / STATUS / TODO / LOG |
| 帮我核对改动 | 说明变更影响 | Git status / diff、验证命令 |
| 检查网页表单 | 解释 DOM 与规则 | 结构化浏览器访问；可写操作取决于权限和策略 |

## 4. 何时该用 GUI，何时不该用

**首选**文件读写、命令、测试和结构化浏览器。它们无需抢占用户鼠标焦点，易于留下验证证据。仅当必须操作原生应用特定窗口，且用户明确允许时才使用 GUI。不要在游戏运行时弹窗、切换前台、移动鼠标或模拟键盘；保护措施并非对所有未知游戏都保证检测。前台系统级输入不能通过普通文件工具绕过许可。

## 5. 版本与边界

- 公开 GitHub **v3.0.1 Release**：文档声明 **12 项 Direct MCP 工具**，且不包含 Blender、Godot、ComfyUI 的专用接口。下载包实际提供的功能才是用户可依赖的能力。
- 作者开发机另有更多能力以及 2026-10-25 Browser V5、GUI V6 的局部测试。**这些不是 v3.0.1 Release 已交付功能**；开发机部署哈希冲突、老进程尚未更新等问题使其不能作为默认发布承诺。
- 远程 MCP 需要支持连接的 ChatGPT 账号、用户自己的认证 Tunnel、电脑端设置和授权。MiceHole **不会**解锁官方 Codex、增加额度或绕过账号规则。
- 任意本机命令权限不等于沙箱隔离；不要使用管理员权限运行。密钥、Cookie、浏览器个人 Profile、SSH 凭据和私人文件不得放到示例项目里。
- 朋友的不同 Windows 账号 / 环境、断线恢复、全部 GUI 浏览器场景和更强凭据隔离仍须独立验收。

## 6. 首次部署与故障排查

请按 [v3.0.1 Windows 安装教程](INSTALL-V3.zh-CN.md) 安装，执行随包 Doctor，并确认实际发现的工具数与对应 Release 文档一致。先在没有隐私内容的目录演练：读取文件 → 用测试脚本运行 → 看退出码 → 审查 diff → 收尾。如果手机端找不到工具，检查账号连接权限、Tunnel、电脑运行状态、网络代理和授权；不要为了排查而关闭重要安全门或公开无认证端口。
